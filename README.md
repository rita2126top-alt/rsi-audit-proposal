# RSI-Audit

## 有限验证预算下，自改进代码智能体的可信评测

**TOKEN-IGNITION 申请方向：RSI 评测（`eval`）**  
**申请账号：`rita2126top-alt` · 方案日期：2026-10-28 · 版本：0.1.0-proposal**

项目仓库：[rita2126top-alt/rsi-audit-proposal](https://github.com/rita2126top-alt/rsi-audit-proposal)。

本项目研究一个可检验的问题：代码智能体逐轮改进自己的提示与修复策略时，在同样的验证机会和资源上限下，应该反复检查同一批题、每轮换一批题，还是只在最后做一次较大的验证？我们用完全独立的末次审计，衡量终态收益、晋升决策的偏差和真实算力成本。

**当前交付是研究 proposal、预注册协议草案和核实后的文献/版本记录。没有完成 GPU 实验，没有本项目的性能结果，也不代表资助方已立项或通过评审。** 完整实验执行器、隔离运行设施和统计分析程序是获批后第一阶段的开发内容。

### 最小研究范围

- 一个固定模型：Qwen2.5-Coder-7B-Instruct；不做模型训练。
- 一个固定 Python 评测平台：EvalPlus；HumanEval+ 164 题、MBPP+ 378 题，共 542 道原始任务。
- 三种验证预算分配策略：固定分片复用、一次性轮换分片、末次一次验证。主比较预先固定为“轮换 vs 复用”。
- 六条随机搜索轨迹、每条六轮；每轮两份候选持久 harness 配置。
- 7 天最小试跑，28 天完成；申请单卡 A100 80GB，试跑 48 卡时，全程 480 卡时（包含试跑）。

这里的“相同预算”指相同逻辑评测额度与 token 上限。不同策略实际消耗的 token、GPU 时间和独立题目数量会分别报告，不假装它们天然相等。公开旧题也不能证明模型训练数据无污染。

### 本地检查

```bash
python3 tools/validate_package.py
```

此命令仅检查申请字段、文献键、文件与预算一致性，不下载模型、不执行生成代码、不运行 GPU 实验。正式实验参数见 [configs/study.json](configs/study.json)，其中需要在试跑后锁定的项目明确标为待冻结。
