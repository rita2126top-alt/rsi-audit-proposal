# 算力预算与可行性关卡

## 申请数额

卡型：**A100 80GB，优先单卡**。试跑：**48 GPU 卡时，7 天内**。完整：**480 GPU 卡时，28 天内，包含前述试跑**。不是 48+480，也不是已获批的额度。

卡时为 GPU 数量乘实际占用小时；CPU 测试、存储和数据准备另记，不折成 GPU 运行成果。硬件替换需重新记录吞吐和预算，不把不同型号卡时当作等价性能。

## 任务量上界

下述计数是正式主试验的未缓存上限，不包含试跑与故障恢复重试；后两项仍需从 480 卡时总预算中支出。

采用预期 128/192/222 划分、3 组、6 个搜索种子、6 轮、每轮 2 候选。每条轨迹包含最多两次 solver 调用，不能把轨迹数与 API 调用数混为一谈。

| 每组每 seed 的阶段 | 公式 | 任务轨迹 |
| --- | --- | ---: |
| 初始策略开发评估 | 128 | 128 |
| 六轮候选开发评估 | 6 × 2 × 128 | 1,536 |
| 验证：候选与父版本均计费 | 6 × 32 × 2，或 192 × 2 | 384 |
| 初始版本 + 六轮赢家审计 | 7 × 222 | 1,554 |
| 每组每 seed 合计 | | 3,602 |
| 三组、六 seed 合计 | 3,602 × 3 × 6 | **64,836** |

另有 `3 × 6 × 6 × 2 = 216` 次候选提议，每次最多 1024 输出 token。solver 每条轨迹输出合计上限 2048 token，因此未缓存保守上限为 132,784,128 输出 token；输入上限 8192 token/轨迹，相应逻辑上限 531,136,512 输入 token。计数不是实际消耗预测，也不含失败重试预算；任何重试必须从资源余量中扣除并记录。

审计集合无需包含全部 12 个开发候选；B0 和六个进入门控/终态链的赢家足以评估晋升与父版本。精确缓存可降低重复 B0、重复父版本和未变化 checkpoint 的成本。上表为了避免漏算未扣缓存；实际执行不应主动制造无用重复。

## 分阶段预留

| 阶段 | A100 卡时计划 |
| --- | ---: |
| 最小试跑、吞吐测量、兼容与完整性检查 | 48 |
| 正式提议、开发评估和门控 | 240 |
| 冻结后的终态与历史审计 | 144 |
| 必要复核、故障恢复和余量 | 48 |
| 合计 | **480** |

这些是分配计划，不是测得的运行耗时。试跑需同时测输入预填充、输出解码、不同题型、batch、两次调用比例和 CPU 测试尾延迟。不能只用显存够放 7B 或一个理想 token/s 断言可以完成。

## 7 天试跑验收

1. 只使用正式开发分区内部的临时切分，完成三种策略各两轮的端到端闭环；不读取正式确认/审计结果。
2. 证明候选改变会影响开发行为，量化变化幅度；不要求出现正提升。若所有候选等价，报告动作空间缺乏实验信号。
3. 验证计分来源、失败分母、越权写入、隐藏文件读取、联网和伪造 stdout 的处理；不能用普通子进程退出码代替全部完整性证据。
4. 生成实际成本报告，以分阶段平均值及保守尾部余量外推完整工作量；报告估算区间。
5. 在确认和审计不可读的条件下冻结模型/环境、划分承诺、动作空间、阈值、种子、统计程序和资源计费规则。

## 预先规定的缩减与停止

- 三组方案预计超出 480 卡时：先删除解释性的 Terminal 组，保留 Fresh/Reuse 的六种子六轮主比较、终态和对应晋升诊断。两组未缓存逻辑上界是 43,224 轨迹；重新给出成本估计并在正式试验前登记。
- 主比较仍超预算、数据隔离不成立、动作空间没有可测变化或计分可伪造：停止完整研究，公开试跑失败报告，交由资助方复议。
- 不因某 seed 成绩不好而停止或重抽；不使用审计成绩选择分支、模型、阈值或保留组别。
- 运行到 GPU 总硬上限即停止新增任务，保留不完整记录，明确哪些推断不能作出。平台错误和算法错误分别记录。

“相同资源上限”不等于“相同实际成本”。报告收益与成本时保留省下的算力，绝不为匹配消耗空跑。
