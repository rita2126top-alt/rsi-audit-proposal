# 实验协议与预注册草案

版本：0.1.0-proposal，2026-10-28。此文约束未来实验；不代表实验代码已经运行。正式配置、任务清单和容器摘要将在第一周试跑之后、读取任何审计结果之前登记。

## 1. 实验单位和推断目标

研究对象是持久 agent harness 的迭代更新。权重冻结，同一个模型在当前持久策略的上下文中生成下一次策略修订。每轮有两个候选，使用开发集择优，只有一个进入门控。修订影响后续任务和下一轮提议，区别于只重写一道题的答案。

主比较为 Fresh 对 Reuse 的第六轮终态审计成功率差。Terminal 为解释性对照。这个设计比较验证预算分配的整体策略；独立题量、验证精度、反馈频率和路径依赖均属于策略的一部分。没有在统计上单独识别自适应过拟合的纯因果效应，也不证明大规模、开放式、无限期的 RSI。

使用同一冻结题目划分和六个 proposer seeds。各组从同一 B0 出发，配对使用相同随机种子和资源上限；不同晋升决定会使后续候选不同。greedy solver 的重复调用不能被当成新的随机证据。

## 2. 数据划分

输入固定为 HumanEval+ v0.1.10 与 MBPP+ v0.2.0，共 542 原始任务，哈希见 `evidence/baseline-lock.json`。预期开发/确认/审计规模为 128/192/222。

划分由数据管理程序完成，先以原始任务 ID 聚合同题测试，再根据规范化题面/参考函数的精确重复和可复核的近重复规则建立任务族。完整任务族不得跨分区。来源分层后按事先承诺的随机种子分配，不能用模型得分决定划分；人工复核仅处理内容重复，不看任何候选结果。

目标 128/192/222 是方案规模，不是已生成的真实 manifest。分组导致不能精确分配时，优先保留任务族及至少 200 道审计题；以最近可行分片大小重新计算门槛、逻辑额度和统计功效，在主试验前发布协议变更。不得临时从审计集中补开发题。若必须缩减实验，遵循 `COMPUTE.md` 的预定规则。

第一周的工程试跑使用开发分区内部的模拟验证/模拟审计切分。正式确认集和审计集的结果此时不能被研究者或 agent 查看。完整 benchmark B0 的跑分也要等搜索完全冻结后才可公开；原论文参考数字无此限制。

主试验前发布 manifest 承诺：完整任务列表与盐存于独立权限域，只公开带盐摘要和来源数量。试验结束解封盐和列表，使外界可检查是否换题。哈希承诺只提供可追溯性，不是秘密数据的访问控制。

公开题可能进入模型预训练；隔离只能限制本次搜索过程的读取和反馈，不能证明训练无污染。结论限制在这一固定模型/平台。

## 3. 允许修改的状态

候选是 JSON，仅允许：`strategy_prompt`（最多 1024 个冻结 tokenizer token）、`feedback_style`（预定义枚举）、`repair_order`（预定义枚举）。不接受可执行插件、依赖、shell 命令、计分补丁或任意代码模块。字段以外的内容拒收。

两次 solver 调用为统一上限；所有 solver 输出合计最多 2048 token，输入合计最多 8192 token。solver temperature=0；proposer temperature=0.7，top_p=0.95，独立 seed，单次输出至多 1024 token。推理引擎的种子和数值确定性边界在试跑中记录。无效 JSON 可占用一次已计费提议额度后记为无效，不无限重试。

单轨迹只能把题目公开示例及自己代码的运行反馈用于一次修复。隐藏确认/审计测试仅在最终程序冻结后运行，结果不会用于该题修复。最终只提交一个程序；失败、截断或超时按同一规则计失败。指标是轨迹级成功率，不称为原始模型 pass@1。

候选提示不能增大调用次数、上下文容量或工具能力。候选无法读取当前处于哪一评测分区，确认服务不向 agent 暴露任务 ID。禁止从题目 ID 决定特殊答案。所有动作在统一解释器中执行，解释器自身被冻结。

## 4. 三组门控

共同确认池为六个互不重叠、来源比例尽可能一致的 32 题分片。分片顺序由每个搜索 seed 在预定规则下排列。Reuse 取排列首个分片重复六轮，Fresh 按排列依次使用。这样复用组不会永久绑定某一个特别容易或困难的面板；同一 seed 第一轮面板相同。

Reuse/Fresh 每轮都比较本轮开发集赢家 c 与当前已晋升父版本 p，在同一题上计算 `d_i = success(c,i) - success(p,i)`。当 `sum(d_i) >= 2` 时晋升，否则保留 p。两者最多六次门控。

Terminal 不接收中间确认信号；每轮比较当前临时状态与两个候选的开发分数；只有候选严格改善才替换当前状态，平局保留当前状态；两个改善候选平局时按后述 token/SHA-256 规则决定。当前状态的开发分数复用已有可信记录，不增加轨迹额度。第六轮将最终工作状态与原始 B0 比较，在完整 192 题上 `sum(d_i) >= 12` 则部署，否则部署 B0。不是从审计结果中回溯挑选最好历史状态。

默认门槛均为 6.25 个百分点，属于工程经验阈值。32 题的得分粒度为 3.125 个百分点，小面板有明显噪声；不宣称这些规则具有 95% 安全晋升保证，也不照搬 VALVE/Ladder 的理论。

开发集候选平局时先选输出 token 更少者，再按候选配置 SHA-256 字典序决定，规则对所有组一致。确认未晋升不追加候选。计划执行完六轮；剩余资源不用于额外搜索。

确认服务只把接受/拒绝信号反馈给提议过程。其任务级结果由监督器密封保存，搜索阶段不可查询。该反馈限制对两个逐轮组相同。

## 5. 隔离、日志和计分

控制面、候选推理/工具工作区、候选代码沙箱与计分器分属不同权限域。候选工作区无网络、无云凭据、无正式测试挂载、无控制面或日志写权限。模型在试验前下载，离线运行。

不能直接把未加固的 `evalplus.evaluate` 当作完整安全边界。拟实现的执行监督器在外部持有参考测试和期望结果；不可信代码在独立 OS sandbox/进程中只接收本次调用输入，返回受限序列化结果。监督器验证协议、收集退出/超时信息并与参考值比较。持久日志由监督器独占写入，不从候选目录回收“分数 JSON”。评分器只聚合可信记录，永不在其进程内 import/exec 候选。

执行环境限制 CPU、内存、进程数、文件大小和墙钟时间；无宿主 Docker socket、无额外挂载、无出网，隐藏测试不进入候选可读文件系统。生成程序的 stdout 只是待检查的输出，不是授权的计分通道。若某些 EvalPlus 测试无法在该隔离结构下正确支持，先报告兼容缺口，不能以关闭隔离掩盖问题。

每条可信记录至少包含 study/config/model/data 哈希、seed、arm、round、候选/父版本哈希、分区、任务 ID、最终程序哈希、实际输入/输出 token、调用次数、可信状态、CPU 秒、GPU 时间归属和缓存标记。计分器验证键唯一性、任务总数、状态枚举和哈希链；禁止缺失任务静默退出分母。

正式试验前必须检验：候选打印伪分数、写日志路径、读取审计目录、尝试联网、异常退出和超时等情形不能伪造通过记录。程序逻辑缺陷、平台漏洞和操作者越权不可能靠本提案文字排除；结果必须给出实际验证证据和残余限制。

## 6. 冻结与审计

所有组和所有 seed 搜索完成后，提交六轮状态和接受记录的哈希清单，再统一解封审计权限。审计运行任何一个 checkpoint 后，不能继续生成或选择候选。

主结果固定使用第六轮最终部署状态。诊断审计最多覆盖 B0 加六个进入门控的赢家；所有父版本都在这条集合中。无需为全部开发阶段落选候选做审计；因此不报告总体“正确修改拒绝率”。Terminal 中间状态的审计只是描述性，不将其视为已晋升部署。

精确相同的模型/配置/程序/任务结果允许在统一、预先规定的缓存规则下复用。逻辑额度照样记账，实际模型调用与缓存命中另记。不会为了制造相同 GPU 时间而重复烧算力。在线进度只使用开发/确认的授权信号；审计账本不参与资源重新分配。

## 7. 指标

令 `S(h,i)` 为最终程序在任务 i 上通过全部冻结测试的 0/1 记录。

1. **主指标**：`mean_seed,task[S(Fresh_final,i)-S(Reuse_final,i)]`，用百分点报告；来源总体权重由冻结审计 manifest 决定。另分别报告每组相对 B0 的差值。
2. **次要诊断 optimism**：对同一候选 c 与父版本 p，`O = mean_confirm[S(c)-S(p)] - mean_audit[S(c)-S(p)]`。同时报告所有门控赢家以及接受子集，注明选择条件。两种不同验证策略不能只比较原始面板分数。
3. **审计退步晋升**：已接受修改的审计差值；点估计负差比例为描述性统计。只有经历史比较校正后的单侧区间上界低于 0，才称“审计支持退步”；下界不低于 0 称“审计支持无退步”；其余“不确定”。零接受时比例为 NA，不能记为 0% 以冒充完美门控。
4. **成本**：实际输入/输出 token、逻辑与物理调用数、GPU 型号/卡时、CPU 秒、缓存命中率、无效提议、超时、开发/确认/审计阶段成本。收益/成本保留负号；零增益不解释为“无限高效”。
5. **历史回撤**：仅描述预定 checkpoint 审计曲线，并注明其最大值存在选择偏差；不能用曲线最高点替代终态主结果。

## 8. 统计和功效边界

主对比只有 Fresh–Reuse 一个。以相同任务上的配对差为基础，分别对来源层内的任务族与六条搜索轨迹重采样，保持组间配对；公开逐 seed 结果和 95% 区间。两个维度是交叉而非嵌套独立，代码必须正确处理。区间属于有限任务/有限搜索条件下的不确定性描述，不能推广到所有模型和真实仓库任务。

样本规划应使用试跑开发任务的配对不一致率 q 作粗略计算。例如忽略更复杂的聚类时，222 题、q=0.20 对应配对差标准误约 3 个百分点，95% 区间半宽接近 6 个百分点；这一示意不证明 5 个百分点提升有足够检验功效。六个种子不能补偿题目多样性不足。以开发数据做模拟后，报告可检测范围；不可借助正式审计来调参数。

历史晋升多重比较使用预先约定的 Holm 家族校正单侧检验，并配套可解释的调整区间/状态；所有方法与计算实现必须在审计前冻结。对每 seed 有最多六个依赖晋升，不能对所有晋升事件直接套独立二项分布置信区间。分母、零晋升、未完运行和各类失败均公开。

没有显著差异不等于等效；若要声称非劣效，必须事先另设有功效支持的界值，本项目不作此承诺。

## 9. 协议变更

试跑可以修复工程问题并冻结软件环境，但只能使用开发数据。任何改动必须记录原因、时间、受影响参数及是否已经读取确认/审计结果。主试验开始后如计分或数据发现错误，保留原记录，将受影响整组统一重新评估或标为作废；不只重跑不喜欢的 seed。终态审计解封后不再优化，新增实验须作为独立、明确标注的后续研究。
