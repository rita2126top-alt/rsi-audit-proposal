元数据核实至 2026-10-28；完整作者与可导入条目见 [references.bib](../references.bib)，核验来源见 [sources.json](../evidence/sources.json)。以下区别是本研究的拟议定位，并非已经证明的新颖性或性能结果。

| 文献 | 与本项目相关的已有贡献 | RSI-Audit 的定位 |
| --- | --- | --- |
| Hu et al., *Automated Design of Agentic Systems* (2024), [arXiv:2408.08435](https://arxiv.org/abs/2408.08435) | 自动生成和搜索 agent 系统设计。 | 固定底座与受限动作空间，比较验证预算分配；不声称首创自动 agent 设计。 |
| Zhang et al., *Darwin Godel Machine* (2025), [arXiv:2505.22954](https://arxiv.org/abs/2505.22954) | 维护候选档案并以代码任务评估系统的自修改。 | 借鉴持久自改进的实验对象；不声称复现其规模或开放式能力。 |
| Hui et al., *Qwen2.5-Coder Technical Report* (2024), [arXiv:2409.12186](https://arxiv.org/abs/2409.12186) | 提供代码模型及公开评测结果。 | 固定开源权重底座；原成绩与本地重新建立的 B0 分开。 |
| Liu et al., *Is Your Code Generated by ChatGPT Really Correct?* (2023), [arXiv:2305.01210](https://arxiv.org/abs/2305.01210) | 用更充分的测试揭示原测试遗漏的代码错误。 | 采用冻结增强测试作为操作性正确性标准；通过有限测试不等于程序正确性的证明。 |
| Dwork et al., *The reusable holdout* (2015), [Science DOI](https://doi.org/10.1126/science.aaa9375) | 为自适应数据分析设计可重用 holdout 方法。 | 作为问题基础；本项目简单经验门控没有实现该算法，不继承其保证。 |
| Blum & Hardt, *The Ladder* (2015), [PMLR 37](https://proceedings.mlr.press/v37/blum15.html) | 处理适应性提交中的排行榜可靠性。 | 说明反馈策略需要被研究；一比特反馈本身不是 Ladder 理论保证。 |
| Wang et al., *Certified Long-Horizon Code Agent Evolution via Validation-Gated Skill Optimization* (2026), [arXiv:2609.32990](https://arxiv.org/abs/2609.32990) | VALVE 的持久技能门控；明确分析自适应面板复用与 holdout 大小。 | 研究开源 7B、短周期和资源上限下的策略代价。Reuse 是受控简化策略，不标为完整 VALVE 复现，也不说前人忽略复用问题。 |
| Zhang et al., *Who Verifies the Verifier?* (2026), [Amazon Science](https://www.amazon.science/publications/who-verifies-the-verifier-co-evolving-inspectable-graders-with-self-improving-agents) | 演化可检视验证器组合；展示下游收益不能单独证明验证器可靠。 | 本研究冻结可执行评分器，改变验证数据的使用方式，不再提出另一个验证器共演化框架。 |
| Wang et al., *The Verification Horizon* (2026), [arXiv:2606.26300](https://arxiv.org/abs/2606.26300) | 从多个维度分析代码 agent 的验证信号及其限制。 | 提供背景；本项目的具体三组比较仍需实测，不能从该论文推断 Fresh 必胜。 |

## 本项目可以支持的贡献声明

在固定模型和可执行评分器下，公开一套有限预算的验证分配实验：同步控制候选额度和 token 上限，记录实际成本；所有搜索结束后统一审计预先保存的终态与晋升链；报告改进、退步、不确定和没有晋升的情况。结果可以指导有限算力下怎样分配验证资源。
